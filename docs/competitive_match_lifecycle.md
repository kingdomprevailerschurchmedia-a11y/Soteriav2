# Competitive Match Lifecycle

Soteria implements a strict, server-authoritative lifecycle for 1v1 Versus matches.

## Match Lifecycle States

1.  **CREATED**: Match document generated by matchmaking or challenge acceptance.
2.  **WAITING**: Waiting for both players to enter the match orchestrator.
3.  **READY**: Both players are in the orchestrator.
4.  **COUNTDOWN**: Both players have confirmed readiness. A 3-second synchronized countdown begins.
5.  **ACTIVE**: Gameplay is in progress. The client periodically syncs score and question progress to Firestore.
6.  **FINISHING**: One or both players have completed the questions.
7.  **PROCESSING**: Server is calculating the final result, rank changes, and rewards.
8.  **COMPLETED**: Final result is available. Players are shown the result screen.
9.  **ABANDONED**: A player left the match before completion.

## Result Processing

The result processing is intended to be handled by a backend service to ensure competitive integrity. The client waits for a `match_results` document to be created before displaying the final outcome.

### Key Metrics
- **Winner/Loser**: Determined by final score, or response time in case of a tie.
- **Rank Change**: RP gain/loss based on the outcome and rank differential.
- **Rewards**: XP and Coins granted based on performance and win bonus.

## Post-Match Experience

- **Result Reveal**: Victory, Defeat, or Draw banners with high-impact visuals.
- **Score Comparison**: Real-time scores and opponent identity.
- **Performance Summary**: Accuracy, correct answers, and response time.
- **Rematch**: A direct action to challenge the same opponent again.

## Technical Implementation

- **VersusMatchOrchestrator**: Manages the UI transitions between match states.
- **MatchLifecycleController**: Handles readiness confirmation and state updates.
- **VersusProgressSync**: Synchronizes local quiz state to the remote match document.
- **MatchResultRepository**: Fetches the authoritative result from Firestore.
