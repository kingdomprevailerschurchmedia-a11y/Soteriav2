# Competitive Activity Timeline

The Competitive Activity Timeline serves as Soteria's persistent competitive career journal. It provides a chronological record of meaningful accomplishments, separate from the temporary nature of notifications.

## Architecture

The timeline is a **Persistent Read Model** stored in Firestore. Events are generated by authoritative systems (Ranking, Achievements, Rewards) and captured by the `CompetitiveEventObserver`.

### Data Flow

```mermaid
graph TD
    AUTH[Authoritative Systems] --> OBS[CompetitiveEventObserver]
    OBS --> |CompetitiveEvent| ACT[Activity Event Store]
    ACT --> |Firestore| DB[(users/{userId}/competitive_activity)]
    DB --> |Paginated Query| PROV[activityFeedProvider]
    PROV --> UI[CompetitiveActivityScreen]
```

## Activity Event Model

### `CompetitiveActivityEvent`
- `id`: Unique identifier (usually a deduplication key).
- `type`: Category of the competitive event.
- `importance`: Visual weighting (Low, Normal, High, Milestone).
- `createdAt`: Immutable server-authoritative timestamp.

## Event Types Supported

- **RANK_PROMOTED / RANK_DEMOTED**: Major career shifts.
- **ACHIEVEMENT_UNLOCKED**: Permanent accomplishments.
- **REWARD_RECEIVED**: Resource gains.
- **SEASON_STARTED / COMPLETED**: Milestone lifecycle events.
- **PERSONAL_BEST**: Breaking records in score or position.

## Implementation Details

- **Pagination**: Uses cursor-based loading to scale to thousands of events.
- **Immutability**: Once an event is recorded in Firestore, it is treated as a historical record.
- **Idempotency**: Events use deduplication keys to prevent duplicate records for the same achievement or rank change.
- **Deep Links**: Tapping a timeline item routes the player back to the relevant feature (e.g., Achievement Detail, Profile, or History).

## UI Components

- **Activity Timeline**: A vertical timeline layout with importance-based icons and colors.
- **Activity Detail**: Bottom sheet showing rich metadata for specific events.

## Security

- **User Isolation**: Players can only read their own activity feed.
- **Write Protection**: Activity events can only be created through server-side logic or trusted client observers triggered by authoritative data changes.
